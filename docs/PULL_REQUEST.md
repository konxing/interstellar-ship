# Pull Request

**Title:** `feat: DSX-01 Kairos Horizon procedural 3D modelling workbench`
**Base:** `main` ← **Head:** `feat/spaceship-3d-workbench`

## What

Adds a complete, original, fully procedural 3D modelling project for the
deep-space exploration vessel **ISV Kairos Horizon (DSX-01)**. Every triangle is
generated by this repository's own dependency-free NumPy geometry kernel; there
are no third-party model assets.

Deliverables in this branch:

- **7 glTF-binary assets** (`models/glb/`, 353 864 tris, ~11.5 MB) + manifest:
  complete ship, four deck-level cutaways, interior compartment layout, and a
  fusion torch drive study.
- **Native Blender original** (`models/blend/dsx-01_full_ship.blend`) plus a
  headless Blender bridge (`blender/`) that rebuilds any asset from the same
  spec, keeping `.blend` and `.glb` provably in sync.
- **Offline Three.js workbench** (`viewer/`, vendored three r160): asset
  switcher, per-system isolation, exploded view, camera presets, centrifuge
  spin, wireframe/grid/starfield toggles and a click-to-inspect info panel
  driven entirely by exporter node extras.
- **Software preview renderer** (`scripts/render_preview.py`) and 14 stills in
  `assets/preview/`.
- **Design documentation** (`docs/`): specification, modelling guide, asset
  contract, viewer guide, acceptance criteria.
- **Validation**: dependency-free test suite (43 Python tests + 22 viewer tests), per-asset GLB
  round-trip report, Blender↔Python exporter cross-validation, and a measured
  acceptance report (`reports/`).

## Why

Provides a single source of truth (`shipspec/constants.py`) so models, Blender
scene, previews, viewer metadata and tests can never drift, and a regenerable
pipeline (`scripts/build_models.py`) so the whole vessel can be rebuilt or
extended from source with only NumPy.

## How to review

1. `python3 scripts/run_tests.py` — expect 33 passed.
2. `./scripts/serve.sh` then open `/viewer/` — orbit the ship, toggle systems,
   explode, click parts.
3. Skim `docs/design-specification.md` and `reports/acceptance-report.md`.

## Notes / non-goals

- `main` is untouched beyond the initial skeleton commit; all work is on this
  branch, committed per milestone.
- Materials are PBR factors only (no texture maps) by design.
- Only the full-ship `.blend` is committed to keep the repo lean; the rest
  regenerate via `blender/build_all.sh`.
- No secrets, tokens or personal data are included.
